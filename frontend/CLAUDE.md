# Frontend conventions (loads when working in frontend/) — owner: frontend-engineer

React 19 + strict TypeScript + Vite 8 (rolldown, no esbuild install script) SPA, installable
as a PWA (online to save, ADR-0002). React Aria Components for primitives, Tailwind v4 with
CSS-variable tokens, TanStack Query (memory only) for server state, a small in-house router.
Source of truth: docs/contracts/. Status (2026-11-14): MVP screens complete (tasks 1–15).

## Rules

- **API:** only `api` + `unwrap()`. Never hand-write request/response types (alias in `api/types.ts`). Server data goes through TanStack Query (memory only). Non-JSON responses (CSV export) use `parseAs: "blob"` and an explicit `Accept`.
- **Writes over flaky networks:** creates carry an `Idempotency-Key` made when the form opens, reused on every retry, renewed after success (or when the person chooses "save as new" after `IDEMPOTENCY_KEY_REUSED`). Edits and deletes send `version`; on `VERSION_CONFLICT` refetch and ask, never overwrite silently. On failure keep all input and say so. **Online to save:** mutations default to `networkMode: "always"` (`app/query.ts`), so a write made offline fails at once with `NetworkError` instead of pausing behind a spinner; `useAction` writes call the API directly and already behave this way. Tests: `renderWithApp` merges the app's defaults, so it sees the same mode.
- **Errors:** switch on `code`. `describeError` for copy, `FormError`/`ErrorState` for display (request ID when `diagnostics`), `mapFieldErrors`/`serverErrors` for fields. Sensitive calls (`x-reauth: true`) go through `useReauth()`; destructive ones through `ConfirmDialog`.
- **Roles:** show only what the role allows (owner vs member), but never rely on it; the server enforces everything and the screen handles `FORBIDDEN`/`NOT_FOUND`.
- **Auth:** CSRF token and return path only in memory. The return path and a stashed quick-add draft are bound to the user who left them and dropped when someone else signs in (F-54). Sign-out is done only on a 2xx or 401; anything else keeps the person signed in and says so (F-51); use `<SignOutButton>`, or `signOut({ revoked: true })` after revoking this session. Emailed tokens via `peekLinkToken(path)`, then `clearLinkToken()` after use. Pending-deletion accounts see only `PendingDeletionScreen`. Server-side revocation (password reset, email-change cancel, account deletion) → `forget()`.
- **Money / dates:** integer cents (`parseMoneyInput`, `formatCents`, `<Money>`); no `/100`, `toFixed`, `parseFloat`. Calendar values via `lib/dates.ts`; "today" = `Budget.today`.
- **Device storage:** localStorage only via `lib/preferences.ts` (one commented `eslint-disable-next-line`). ESLint bans `localStorage`, `sessionStorage`, `indexedDB`, `caches`, `cookieStore` as globals and as a property of any object, plus `.cookie` (F-52; proven by `scripts/eslint-storage-ban.test.ts`). The service worker caches the app shell only (`sw/service-worker.js`): `/api/*` is never intercepted, navigations are network-first (fresh `index.html` + CSP when online; the matching precached shell offline), hashed assets cache-first by path with `ignoreVary`, old caches dropped on activate, updates only through the "Reload" banner. `check-dist` fails if the precache lists an API path, a source map or a missing file. No SW in dev or e2e (production builds only).
- **CSP:** no inline script/style, no `style=""`, no `dangerouslySetInnerHTML`. `style={{}}` (CSSOM) is fine. React Aria upgrades that change its injected styles fail `make check`.
- **Styling:** token utilities only. `className` on shared components is layout only; visual options are props (Button: `variant` incl. `selected`, `size`, `shape`, `align`, `weight`), because Tailwind orders utilities by property.
- **Accessibility:** WCAG 2.2 AA; 44 px targets; 16 px inputs; visible labels; one `<h1>` per screen; state never by colour alone; charts `aria-hidden` + text + table; focus moves to `<h1>` on navigation and to confirmations; status inside a sheet/dialog needs its own live region (React Aria modals hide the page). `src/a11y.test.tsx` renders every route through the guard with axe.
- **Page loads:** a page-level pending state is `PendingSlot`/`LoadingState` (viewport). Never draw a lace or a cover yourself; every new `<main>` takes `inert={usePageCovered()}` so the held page can't be tapped or read. Errors and offline messages must be `ErrorState`/`OfflineState` (they end the session); a bare `role="alert"` stays hidden until the cycle ends.
- **Nothing moves under a finger:** a loading region whose final height is unknown (a list, chips) is the last thing on screen; controls that would sit below it render only once it has settled (More, Members, the quick-add sheet). A loader can't reserve the height: list lengths vary, names wrap, and nothing is persisted (ADR-0002). Chips also wait for the recent-use order, which BudgetLayout prefetches (the sheet's own `useTransactions(…, PAGE_SIZE)` key; failure → default order) and the sheet freezes for its session (`keepKnownFirst`: categories added mid-session go last), so Save & new never reorders chips; the just-used category leads on the next open. Gate on data (`data !== undefined`, `!isPending`), never on `isSuccess`, which a failed background refetch turns false. Test with `tappableAfter(loadingRegion, root)` returning `[]`. **Offline with nothing cached, a read is paused, never failed** (`isPending && isPaused`): treat it as settled. Every data-driven screen renders its pending slot as `PendingSlot` (the viewport-centred lace loader, or the in-flow `OfflineState` when paused); where rows are shown below, pass the latched `rowsBelowShown` so it keeps that box until the list arrives, and controls below (Sign out, F-51) don't wait forever.
- **"+" is never ignored:** BudgetLayout renders the sheet in every state at the same tree position; it opens before the budget loads with the amount field focused, waits for the date (`Budget.today`), and shows the budget's error with a retry (404 → NotFound page).
- **Error tracking (F-06, F-07, F-50):** report through `observability/report.ts` only; never import `@sentry/browser` outside `observability/sentry.ts` (it must stay a lazy chunk: `check-dist` fails if Sentry code is in the initial files). Unexpected (non-ErrorBody) API responses are reported from `unwrap`; ApiErrors are not (the backend reports its 5xx). Never put a link token in a query key (fixed keys + `gcTime: 0`).
- **Performance:** initial JS ≤ 150 KB gzip (now ~137 KB; Sentry is a separate ~32 KB lazy chunk): keep every screen lazy and heavy libraries (`@simplewebauthn/browser`, `uqr`) inside lazy screens.
- **Gotcha:** `getByRole("radio")` on a React Aria chip finds the visually hidden `<input>`; click the visible label in browser tests, or a forced click can land on the scrim.

- The service worker exists only in production builds: cover install/offline/update in the Lighthouse / prod-build job, not the dev-server e2e.

## Commands

- `make check` (canonical). Package only: `pnpm --filter ./frontend run lint|typecheck|test|build`.
- `pnpm --filter ./frontend dev`: Vite on 127.0.0.1:5173, proxy `/api` → `API_PROXY_TARGET` **without changeOrigin**.
- `pnpm --filter ./frontend build`: `vite build` + `check-dist` (no preview leak, cache-safe names, no inline script/style, SW precache sane, JS ≤ 150 KB gzip initial, CSS ≤ 30 KB, fonts ≤ 2 files / 60 KB).
- After editing api.openapi.yaml: `pnpm --filter ./frontend gen:api`. After changing the logo: `pnpm --filter ./frontend icons`.
- Style preview: http://localhost:5173/preview.html (dev only); proposal screenshots: `pnpm --filter ./frontend screenshots`.
