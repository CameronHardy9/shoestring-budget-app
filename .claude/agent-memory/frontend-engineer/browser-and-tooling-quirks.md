Verified 2026-11-14 (React Aria 3.53 / RAC 1.22, Vite 8.3, Tailwind 4.3, playwright-core 1.65):

- **React Aria injects `<style>` elements** (usePress on every pressable; usePreventScroll on open modals, iOS WebKit only). Blocked by `style-src 'self'`. Fix = CSP sha256 hashes (`frontend/src/security/csp.ts`, guarded by `scripts/csp-style-hashes.test.ts`). React Aria also reads a nonce from `<meta name="csp-nonce">` if ever needed. ARCHITECTURE's "React Aria doesn't inject styles" assumption was wrong.
- To trigger the iOS path in Chrome emulation you must override both `navigator.platform` AND `navigator.userAgentData` (React Aria prefers userAgentData.platform).
- `crypto.randomUUID` is missing on plain-http LAN origins (make dev LAN=1): use getRandomValues.
- **Tailwind v4 orders utilities by property, not class-attribute order**: a caller's `px-3`/`text-sm`/`rounded-full` does not override a component's base class. Use variant props. `@source not "../preview"` in the shared CSS also starves a preview that imports the same CSS (re-adding `@source` does not win).
- jsdom's `DOMException` is not `instanceof Error`; detect aborts by `name === "AbortError"`.
- Vite dev reloads the page on the first dynamic import of a not-yet-optimised dep: warm up before page.evaluate.
- Local Playwright browser cache (r1208) does not match playwright-core 1.65 (r1254): screenshots use `channel: "chrome"` (installed Chrome), no download.
- Under jsdom, `fileURLToPath(new URL(x, import.meta.url))` fails: Node-side tests need `// @vitest-environment node`.
- Node's fetch/Request rejects relative URLs: the API client builds its base from `window.location.origin` so tests can stub global fetch.
- A React Aria Modal sets aria-hidden on everything outside it, toasts' live region included: status shown while a sheet is open needs a live region inside the dialog.
- `getByRole("radio")` on RAC chips resolves the visually hidden input; a forced Playwright click on it can hit the scrim and dismiss the sheet. Click the label text.
- RAC Button `isPending` uses the live announcer, which leaves role="img" nodes axe flags; exclude `[data-live-announcer]` in axe runs.
- RAC 1.22 deprecates `Radio`/`Checkbox` (use RadioField+RadioButton, CheckboxField+CheckboxButton); eslint no-deprecated catches it.
- Postgres evaluates CHECK constraints on the proposed row BEFORE ON CONFLICT: `INSERT … VALUES (count=-1) ON CONFLICT DO UPDATE` always fails a `count >= 0` check (found in the backend throttle refund, 2026-11-14).
- Service worker cache lookups must use `ignoreVary` (match by path): crossorigin module requests carry Origin, the precache didn't, and a Vary header made every lookup miss (blank page offline).
- `/api/_test/emails` only works with `EMAIL_TRANSPORT=test` (make dev defaults to console); passkeys work headless with the CDP virtual authenticator (`WebAuthn.addVirtualAuthenticator`, ctap2/internal) on localhost.
- **React 19 `lazy` always suspends on first render even if the module is already imported** (the factory promise settles a tick later), then holds the fallback ≥300 ms (FALLBACK_THROTTLE_MS). Preloading modules alone does NOT make route tests deterministic; measured render→heading 360 ms vs 50 ms. Fix (2026-11-16): `lazyScreen()` + `.preload()` renders the loaded component directly; tests that render `<App />` use `beforeAll(preloadScreens)`. Flaky `findBy` under load in App/a11y tests came from this.
- Two concurrent `vitest --coverage` runs in one package clash on `coverage/.tmp`: give one `--coverage.reportsDirectory=…` (with pnpm, no `--` before it).
- Sign-up limit is 10/h/IP and refused attempts count: repeated local journeys lock it; use `/api/_test/clock` briefly (then `{now:null}`) or reset.
- jsdom can't do full-document navigation (`location.replace` is "not implemented" and can't be spied: non-configurable). auth.tsx routes it through the exported `hardNavigation.replace` seam; tests `vi.spyOn(hardNavigation, "replace")` (2026-11-16).
- Lint-rule fixture tests: `new ESLint({ cwd, overrideConfig: { languageOptions: { parserOptions: { project: null } } }, ruleFilter })` + `lintText(code, { filePath })` runs the real flat config on virtual files without a tsconfig program (type-aware rules filtered out). See scripts/eslint-storage-ban.test.ts.
- ESLint `no-restricted-properties` with only `property:` (no `object:`) bans it on ANY object, incl. computed `w["x"]`, aliases and `const { x } = window` destructuring; `no-restricted-globals` only sees bare identifiers.
- **Don't edit anything under frontend/ while `make e2e` runs** (not even CLAUDE.md): the stack serves the live tree through Vite dev and Tailwind's source scan triggers HMR. But the J4 "socket hang up" (2026-11-16) recurred with NO edits: it fails after the test body, in the Node teardown (`emails()` hook), most likely a keep-alive race (tests/support/http.ts `keepAlive: true` agent vs the edge's default 5 s server keepAliveTimeout; J4 idles ~5-6 s on the Node side). Not a frontend bug; owned by test-engineer/ci-engineer. `make e2e` skips the visual stage when the e2e stage fails.
- **Vite merges every `<script type="module">` in index.html into ONE entry**, whose static imports (shared chunks) evaluate before its body: "first import" isn't first in the build. F-50 fix (2026-11-17): the link-token capture is a separate rolldown input injected as the first script (`scripts/boot-script.ts`); `check-dist` proves it via the chunk's hidden source map `sources`.
- **Sentry JS v11 removed `sendDefaultPii`**: use `dataCollection` with every category off (backend does the same). Its fetch transport creates a hidden `about:blank` iframe to find a native fetch once fetch is wrapped: no CSP violation under the app's CSP (smoke-tested in Chrome 2026-11-17). `@sentry/browser` 11.10 with `init` ≈ 32 KB gzip, so it's a lazy chunk.
- **Service worker first install reloaded the page** (clients.claim → controllerchange), wiping the in-memory emailed-link token on a first visit. Fixed 2026-11-17: `reloadOnTakeover` reloads only if a controller existed at registration, or this tab called `applyUpdate` (a tab whose first controller came by claim must still reload after its own "Reload"). Every activate claims, so controllerchange fires in all tabs.
- **Sentry's stack parser turns message lines into frames (F-59):** V8 `error.stack` starts with the whole message; `createStackParser` skips only lines containing "Error: ", and a frame-shaped later message line ("    at x (url:1:2)", or gecko "x@url") becomes the top-most frame (last in `frames`). Empty parsed filenames inherit another frame's filename. Firefox/Safari stacks don't include the message. Sentry's "unknown" function is `"?"`. scrub.ts drops frames whose file / "at fn " / "fn@" text appears in a message after its first line, and bounds file (own `/assets/<name>-<8hex>.js` or `<external>`) and function (identifier chars) independently.
- Vitest fails a test on a real `window` "error" event, even one dispatched by the test: use a plain `EventTarget` stand-in.
- **Error-message text for the Sentry allowlist** (scrub.ts `SAFE_MESSAGES`, 2026-11-17): React 19 prod errors are `Minified React error #N; visit https://react.dev/errors/N?args[]=… for the full message or use the non-minified dev environment for full errors and additional helpful warnings.`; args are `encodeURIComponent`ed (values, no whitespace), so they're cut at the next space before matching. Lazy-chunk failures: Chrome "Failed to fetch dynamically imported module: <url>", Firefox "error loading dynamically imported module: <url>", Safari "Importing a module script failed.". A Vite build without `VITE_SENTRY_DSN` drops the sentry chunk entirely: build with a dummy DSN to inspect it.
- **Vitest installs `Error.prepareStackTrace`** (source maps): stack headers differ from browsers (`new Error("")` with name "TypeError" → "TypeError: " instead of "TypeError"). Tests about V8 header shape must unset it (typed view `Error as unknown as { prepareStackTrace?: unknown }`, restore in afterEach). (2026-11-17)
- **Chrome Web IDL errors' message ≠ stack header**: `fetch("/x")` message "Failed to execute 'fetch' on 'Window': Failed to parse URL from /x", stack header "TypeError: Failed to parse URL from /x". `new DOMException()` has no `.stack` in Chrome. Fetch "Failed to fetch", AbortError, JSON SyntaxError, class-field/constructor-assigned names all match their header (checked in real Chrome via playwright-core `channel: "chrome"`, 2026-11-17).
- **V8 stale-header limit (F-62 b):** a message shortened exactly at a line break after `.stack` was read leaves a stack that still starts with `${name}: ${message}\n`; not detectable from the stack alone (residual reported).
- **TanStack `client.setDefaultOptions()` replaces all defaults** (not a merge): test helpers must spread `getDefaultOptions()` or they silently drop app defaults such as mutation `networkMode`. Mutations default to `networkMode: "online"` → paused (spinner, fetch never called) while `onlineManager` says offline.
- **index.css's global reduced-motion rule only shortens animations** (0.01 ms, 1 iteration, fill-mode none), so anything whose base style is the animation's *start* (e.g. the lace loader's undrawn `stroke-dashoffset: 1`) ends invisible. Give such elements their own `@media (prefers-reduced-motion: reduce)` rule with `animation: none` + the end-state values (done for `.ss-lace-*`, 2026-11-23). The app has no in-app motion preference; only the OS media query.
- jsdom applies no stylesheets and `import x from "...css?raw"` came back empty under vitest here: check CSS rules from a `// @vitest-environment node` test in `scripts/` reading the file with fs (scripts/lace-loader-css.test.ts), and verify computed styles in real Chrome (playwright-core `channel: "chrome"`, `reducedMotion` context option) against `vite preview` of dist.
- Local env (2026-11-23): `pnpm` may be missing from PATH under nvm Node 24 and `make check` refuses (`corepack enable` asked). Without changing the global setup, put a scratchpad shim `exec corepack pnpm "$@"` first on PATH. `make check` lint also needs Docker: `orb start` if OrbStack is stopped. The first run right after starting OrbStack hit two load-timeout flakes (App.test F-54 "someone else signs in", phase2b "member only the list and Leave"); they passed alone and on the rerun.
- Vitest (jsdom, css off) returns `""` for `import x from "*.css?raw"`: CSS checks must read the file in a `// @vitest-environment node` test under scripts/ (which typechecks with tsconfig.node.json: no JSX, so import shared constants from a .ts module, not a .tsx).
- Playwright `page.route("**/api/**")` against the Vite dev server also matches `/src/api/*.ts` modules and hangs the page: match `u.pathname.startsWith("/api/")`.
- `fixed inset-0 m-auto size-fit` centres a fixed box without transforms (verified Chrome 2026-11-24).
- Vitest fake timers (default `vi.useFakeTimers()`) also fake `performance.now()` but not `queueMicrotask`; drive React + timers with `await act(async () => { await vi.advanceTimersByTimeAsync(ms) })`. To simulate a late timer, spy `performance.now` on top of the fake clock with a skew (PageLoader.test.tsx).
- jsdom ignores `inert` (role queries and user-event still reach inert content) and doesn't blur focus when it's applied: tests simulate the browser's blur by hand. Chrome: `Animation.currentTime` of the lace matched the JS boundary within one frame (verified 2026-11-24).
- A `vi.fn()` that returns a rejected promise marks it handled (the spy attaches a `.then` for `settledResults`), so it hides a missing `.catch`. Use a plain function to test that a rejection is swallowed; Vitest then fails the run on a real unhandled rejection.
- **iOS keyboard drops when focus leaves a text field** (2026-11-24, corrected 2026-11-25). React Aria 3.53 `usePress` (pointer path) fires `onPress` on the **click** event (80 ms timer fallback after a long press), and `useRadio`'s label onPress calls `ref.focus()` on the hidden radio, so mousedown preventDefault can't save RAC chips. **Handing focus back failed on the real iPhone:** `keepTextFocus` (#36: refocus in `queueMicrotask`) passed in Playwright WebKit but flickered the owner's keyboard. PR #40 (fix/custom-chips) replaced it: ChipGroup = our own `<button role="radio">` group (no RAC RadioGroup) where a tap fires **no focus events at all** while a text field has focus; every chip has constant width (reserves its selected size) and a selected chip beyond the first six stays; `useKeepFocus` (mousedown preventDefault, for `keepFocus` buttons/segments) and `useSlowPress` (clicks at 70 ms, before RA's 80 ms fallback focuses the control; not confirmed on a device). Never blur and refocus. The installed jsdom 31 **has** PointerEvent (verified 2026-11-25; an earlier note here said it doesn't). A RA `onKeyDown` handler stops propagation unless you call `e.continuePropagation()`: do so for keys you don't handle, or Escape stops closing the modal. jsdom keeps `min(85dvh, calc(... env(...)))` in `el.style.maxHeight`.
- When a focused input unmounts inside a React Aria modal, FocusScope (contain) moves focus back into the scope **later** (jsdom: onto the main Amount), so a "focus ends up on X" test passes even without the fix. To prove a synchronous hand-off, record in a `focus` listener whether the removed element was still in the DOM.
- **Frame-recording without credentials** (2026-11-25): serve a `vite build --outDir <scratch>` from a tiny node http server, playwright-core with `page.route` on `/api/*` + delayed `/assets/OverviewScreen-*` chunks, `serviceWorkers: "block"`, and a rAF sampler (`checkVisibility({visibilityProperty:true})`) logging state changes. Local WebKit (webkit-2388) matches playwright-core 1.65.1; chromium needs `executablePath` to `chromium_headless_shell-1254`.
- `userEvent` stalls under Vitest fake timers with RTL here; use `fireEvent.click` (React Aria treats it as a virtual press) with `act(advanceTimersByTimeAsync)`. mockApi + undici bodies do settle under fake timers.
- Same-commit microtask: a `queueMicrotask` from a layout effect runs after the commit and before paint, and a useSyncExternalStore publish there re-renders before paint too, so "reveal + nav" is one frame.
- **Sideways overflow** (2026-11-25): a grid with no template has an `auto` column, whose minimum is the min-content of everything in it, and `truncate` (nowrap) text counts at its **full** width there even though it clips itself; use `grid-cols-1` (= minmax(0,1fr)). Emulated mobile Chromium grows the layout viewport (innerWidth **and** innerHeight, e.g. 375x667 -> 649x1155), so the fixed tab bar is below the visible screen and taps miss; WebKit keeps innerWidth. `overflow-wrap: break-word` doesn't change min-content (safe globally); `anywhere` does, and in a table it re-shares the columns of names that fit. In Chromium touch emulation React Aria keeps a just-opened modal at `opacity: 0` while waiting for the keyboard: wait ~1.8 s before a screenshot.
